# 脚本自动化编写指南

QZRS Scrcpy 内置脚本功能：用 **JavaScript** 描述一系列"点按 / 滑动 / 输入 / 按键"动作，让软件在设备上自动执行。脚本跑在本机沙箱里，通过 scrcpy 控制通道注入触摸和按键——**和你在投屏窗口里手动操作完全同一条链路**。

打开方式：工具栏的 `</>` 按钮（脚本自动化）。

---

## 30 秒上手

新建脚本，粘贴下面的代码，点「运行」：

```js
log('开始执行')

await tap(540, 1200)     // 点一下屏幕坐标 (540, 1200)
await wait(500)          // 等 0.5 秒
await swipe(540, 1500, 540, 800, 300)  // 从 (540,1500) 滑到 (540,800)，用 300ms
await key('BACK')        // 按返回键

log('完成')
```

**前提**：左侧列表里有一台设备处于投屏中（LIVE 状态）。脚本发给"当前投屏的那台设备"。

### 脚本的复制 / 导入 / 导出

- **复制**：鼠标悬停左侧脚本列表的某一项，右侧浮出的「复制」图标点一下，生成一份 `原名 (副本)`，内容相同、互不影响。
- **导出**：工具栏「↑」按钮，把当前脚本存成 `.json` 文件（默认落在文档目录），方便备份或发给别人。
- **导入**：工具栏「↓」按钮，选中一个 `.json`（也兼容一个文件里放脚本数组）即可导入；同名脚本自动改名 `原名 (导入)`，不会覆盖你已有的脚本。

脚本实际存放在 `scripts/` 目录（每脚本一个 json，位置见脚本面板「打开脚本目录」），想整体备份直接把整个目录拷走即可。

## 怎么拿到坐标？

脚本里的 `(x, y)` 是**投屏画面的像素坐标**（左上角为原点）。

最简单的取法：

1. 打开投屏，进「设置」勾上 **显示按键调试日志**（保存后画面左下角出现调试浮层）
2. 在投屏画面里**用鼠标点一下**你要操作的位置
3. 调试浮层 / 日志里会出现 `touch DOWN (x, y)` —— 这就是坐标

> ⚠️ 坐标和分辨率、横竖屏绑定。改了设置里的分辨率（max_size）、或者设备旋转了，坐标就要重新量。

**更省事：先录一遍，再勾上「循环」。** 点脚本面板的「● 录制」，直接在投屏里正常操作（点击、长按、滑动、**键盘按键**的**间隔**都会被记录），停止后操作会自动转成 `tap` / `swipe` / `key` / `wait` 代码填进编辑器。不想写代码的话，把运行按钮旁边的「循环 [30] 秒」勾上再点运行——整段操作会每 30 秒重播一遍，点「停止」结束。详见下文[录制回放](#录制回放不想手写先录一遍)。

## 录制回放：不想手写？先录一遍

1. 脚本面板点 **「● 录制」**（会自动收起面板）
2. 在投屏画面里正常操作，**手势和键盘都会录**：
   - 单击 → `tap`、按住不放 → `tap(x, y, 时长)`、拖动 → `swipe`
   - 键盘按键 → `key('BACK')`；按住多久写第二参数 `key('A', 1200)`
   - 组合键 → `key('E', 0, 4096)`。Shift/Ctrl/Alt 在**没配映射**时不单独录（它们的作用已经折进
     第三个参数）；如果把它们映射成了游戏按键（技能/跳跃这类），那就是你特意配的动作，照常录
   - 按键映射里的**手势类动作**（tap/hold/repeat/view）→ 直接录成像素坐标的 `tap` / `swipe`，
     摇杆（WASD 这类）整段按住录成一行 `stick(中心, 方向点, 时长)`
     （按方向点 `tap` 算不出位移、只推一次 MOVE 也不动，详见下面 `stick()` 的说明）
3. 点录制条上的 **「停止并生成」**，录到的操作会追加到脚本编辑器（前面留了一行注释分隔）

**两次操作之间的停顿也会录下来。** 比如「点 A → 等 3 秒 → 点 B」，生成的是：

```js
await tap(540, 1200)
await wait(3000)      // 两次操作之间的停顿（≥200ms 才记，按 50ms 取整）
await tap(540, 1560)
```

不记间隔的话，回放时一串点击会在几十毫秒内全发出去，游戏里等于没点到——所以这条很关键。低于 200ms 的连击视为手抖，不会插 `wait`。

键盘录出来长这样（左手 Ctrl+E、按住 W+A 走 600ms、敲一下返回）：

```js
await key('E', 0, 4096)   // Ctrl+E
await wait(350)
await stick(435, 720, 241, 505, 600) // W+A：按在摇杆中心，推到左上，推住 0.6 秒
await key('BACK')
```

按钮录制的映射动作**不需要回放时再挂方案**：脚本操作的是设备本身（触点坐标 / keycode），
换台设备、换套映射都能跑。反过来，如果你想让脚本"按哪个键就动哪个位置"，就在脚本里手写
`tap` 坐标，不要依赖映射。

### 最简单的用法：录完 + 勾「循环」

不用写任何代码：

1. 录一遍操作 → 停止（代码自动填进编辑器）
2. 勾上运行按钮旁边的 **「循环 [30] 秒」**，秒数按需改（1 秒 ~ 24 小时 / 86400；**填 `0` = 连续循环**，整段跑完立即重跑、不空等）
3. 想跑固定遍数就顺手填 **「次数」**（留空 = 不限，跑到点停止；填 `3` 就跑满 3 轮自动停）
4. 点 **运行** —— 整段操作每隔 N 秒重播一次，下方日志每轮打一行 `↻ 第 N 轮完成，50 分后重来（约 21:40:00）`
5. 点 **停止** 结束（面板关掉了也不要紧：投屏区顶部常驻一条「脚本运行中 · 停止」）；填了次数的话跑满后日志打 `✔ 已跑满 3/3 轮，循环结束`，无需手动停

勾选状态和秒数记在本机（localStorage），下次打开面板还是上次的设置。一轮的总耗时 = 录制时的动作耗时 + 最后一轮后的 N 秒，需要更精确的节奏就在脚本里手写 `wait`。

**长间隔怎么确认它还活着（v1.4.10 起）**：

- 等待期间每 5 分钟在日志里打一行 `⏳ 距第 2 轮还有 45 分 12 秒（21:40:00）`，剩余时间与墙钟时刻都有
- 投屏区那条常驻提示条会显示**最近一条日志**（面板关着也看得见），循环间隔 50 分钟时它就是你的"心跳"
- 计时按**墙上时钟**算，不是"再等 N 毫秒"：电脑睡眠 / 休眠醒来后按真实时间对齐，已经过点就立刻跑下一轮；等待用 30 秒一段切分，任意时刻点停止都能立刻生效，不会卡在长定时器里
- 如果日志里出现 `会话已断开，脚本中止`，说明投屏会话掉了（设备休眠 / USB 松动 / ADB over TCP 掉线）。**v1.4.14 起会自动重连并从头重跑**：日志会连续记录 `⚠ 会话断开…将自动重连并重跑` → `⏳ 尝试重连设备…` → `✔ 会话已重建，自动重跑脚本…`。约 60 秒（每 3 秒一次、最多 20 次）内设备恢复就自动续跑；超过则 `✘ …放弃自动重跑`，此时需手动重新投屏再运行

> 间隔 3000 秒（50 分钟）这类长周期，务必确认电脑的**电源计划不会让它睡眠**（Windows 默认 10~30 分钟无操作就睡）。睡眠期间进程被冻结，虽然唤醒后能按墙钟补跑，但设备那边可能已经锁屏，操作会打在锁屏界面上。

录出来的是最朴素的顺序代码，适合当骨架——之后手工加 `waitImage`、判断、多段循环就好。录制期间可以随时点停止，不录任何操作直接停止则不改动编辑器内容。

## API 参考

### `tap(x, y, duration?)` — 点按

```js
await tap(540, 1200)        // 普通点击（按下约 60ms 后抬起）
await tap(540, 1200, 800)   // 长按 800ms
```

### `swipe(x1, y1, x2, y2, duration?)` — 滑动

```js
await swipe(540, 1500, 540, 800)         // 从下往上滑，默认 300ms
await swipe(540, 1500, 540, 800, 80)     // 快速甩动（快扫）
await swipe(100, 100, 100, 2000, 2000)   // 慢慢拖动 2 秒（拖进度条）
```

内部按约 16ms 一步插值 MOVE 事件，快扫、慢拖都能被 App 正确识别。`duration` 最小 30ms、最大 60 秒。

### `text(str)` — 输入文本

```js
await text('hello world')
await text('你好，中文也可以')
```

一次最长 300 字节（中文每个字 3 字节，约 100 个汉字）。**只对有焦点的输入框生效**——先 `tap` 点一下输入框再 `text`。

### `key(name, duration?, metastate?)` — 按键

```js
await key('BACK')          // 返回
await key('HOME')          // 回主页
await key('ENTER')         // 回车（搜索框里触发搜索）
await key(4)               // 也可以直接写 Android keycode 数字
await key('VOLUME_UP', 0)  // 第二个参数是按下时长 ms，0 = 瞬按
await key('E', 0, 4096)    // 第三个参数是 metastate：4096 = CTRL（Ctrl+E）
```

可用的按键名：

| 名称 | 按键 | 名称 | 按键 |
|------|------|------|------|
| `HOME` | 主页 | `ENTER` | 回车 |
| `BACK` | 返回 | `DEL` | 退格 |
| `APP_SWITCH` | 最近任务 | `SPACE` / `TAB` / `ESC` | 空格 / Tab / Esc |
| `POWER` | 电源 | `UP` / `DOWN` / `LEFT` / `RIGHT` | 方向键 |
| `VOLUME_UP` / `VOLUME_DOWN` | 音量 | `PAGE_UP` / `PAGE_DOWN` | 翻页 |
| `MENU` / `SEARCH` / `CAMERA` | 菜单 / 搜索 / 相机 | `CALL` / `ENDCALL` / `HEADSETHOOK` | 接听 / 挂断 / 耳机键 |
| `A` – `Z` | 字母键 | `0` – `9` | 数字键 |

> 常用 metastate 值：`4096`=Ctrl、`1`=Menu(Alt)、`2`=Shift、`65536`=Meta。组合写法如 `key('A', 0, 4096)` = Ctrl+A（是否生效取决于 App 自己处理）。

### `stick(xc, yc, xd, yd, holdMs)` — 推摇杆（推荐）

```js
await stick(540, 1200, 430, 1000, 800)   // 按在中心(540,1200) → 推到左上 → 推住 0.8 秒 → 抬起
```

四个点必须都对，少一个游戏就没反应：

| 要素 | 引擎实际动作 | 少了会怎样 |
|---|---|---|
| 落在**摇杆中心** | `DOWN(中心)` | 游戏把落点当原点，位移恒 0 |
| **跨一帧**才推 | 等 40ms 再发 `MOVE` | DOWN/MOVE 落在同一输入帧被合并，原点仍是方向点 |
| 推出**方向点** | `MOVE(方向点)` | 手指没动，方向算不出来 |
| 按住期间**持续** `MOVE` | 每 33ms 补一次，共 `holdMs/33` 次 | 手指不动的那段时间游戏收不到事件，人物立刻停 |

`holdMs` 默认 0（只推一下方向点），单位毫秒，最大 60000。时序与键位映射里的 WASD 摇杆完全一致，
所以**录制出来的摇杆就是一行 `stick(...)`**，回放不用挂方案、换设备也能跑。

### `touchDown(x, y)` / `touchMove(x, y)` / `touchUp()` — 低层手指控制

`stick` 表达不了的组合才用这三个（比如推一半停住、换方向、拉住不放等自定义轨迹）。
一般摇杆直接用 `stick()` 就够了 —— 手写这套要自己补齐「跨帧」和「持续 MOVE」，很容易踩坑。

```js
await touchDown(540, 1200)   // 手指落在摇杆中心
await touchMove(430, 1000)   // 推到左上（方向 = 当前点 − 落点）
await wait(800)              // 一直推着走 0.8 秒
await touchUp()              // 抬起
```

- 没 `touchDown` 就 `touchMove`、或者重复 `touchDown` 都会报错提示。
- `touchUp` 是幂等的，没按着时调用不报错，可以放心写在收尾里。
- **脚本报错 / 被停止 / 忘了写 `touchUp`，引擎都会自动抬手**，不会把手指永久按在屏幕上。

### `wait(ms)` — 等待

```js
await wait(1000)     // 等 1 秒；最大 600000（10 分钟）
```

### `waitImage(name, opts?)` — 截屏找图，等到出现为止

脚本最大的痛点是"固定坐标会失效"（弹窗、广告、加载快慢都会让界面偏移）。`waitImage` 用**截图找图**解决：先框一块模板（按钮/图标），脚本运行时反复截屏，等这块图出现再点它。

```js
// 第一步：脚本面板点「截取模板」，在截图上拖框保存（比如存成 start_btn）
// 第二步：脚本里等它出现并点击
const p = await waitImage('start_btn')
if (p.found) {
  await tap(p.x, p.y)   // p.x/p.y 就是模板中心在投屏里的坐标
} else {
  log('15 秒内没等到开始按钮，跳过')
}
```

可选参数：

```js
await waitImage('start_btn', { timeout: 15000, interval: 500, threshold: 0.85 })
// timeout：最长等多久（默认 10 秒，范围 1–120 秒）
// interval：每次截屏间隔（默认 800ms，范围 200ms–5 秒）
// threshold：相似度阈值（默认 0.9；模板截图后界面有轻微变化可降到 0.8 左右）
```

- 找到 → `{ found: true, x, y, score }`，坐标已换算好，直接喂 `tap`
- 超时 → `{ found: false, x: -1, y: -1 }`（**不报错**，脚本自己决定跳过还是重试）
- 模板名不存在 → 直接报错（提示先去「截取模板」）
- 已保存的模板显示在面板左列「模板」区：**点一下就把 `await waitImage('名字')` 插到光标处**，hover 出垃圾桶可删除

> ⚠️ 模板尽量框**按钮本体**而不是整块屏幕：框越小越准，也别框纯色区域（纯色没法定位）。设备分辨率设置改过之后，旧模板要重新截。

### `getPixelColor(x, y)` / `findColor(color, opts?)` — 读色 / 找色

找图（waitImage）对**纯色 / 低纹理**区域不灵（血条、纯色按钮、状态灯）。这两个 API 直接比颜色：

```js
// 读一个点的颜色（视频坐标）
const c = await getPixelColor(540, 1200)
log(c)   // { r: 255, g: 0, b: 0, hex: '#ff0000' }
if (c.r > 200) log('这个点是红的')

// 全屏找第一个红色（容差 15）
const p = await findColor('#ff0000', { tolerance: 15 })
if (p.found) await tap(p.x, p.y)

// 只在左上 1/4 区域找，颜色用 {r,g,b} 也行
const q = await findColor({ r: 255, g: 0, b: 0 }, {
  tolerance: 20,
  region: { x: 0, y: 0, w: 540, h: 1200 }
})
```

- `color` 支持 `'#RRGGBB'`、`'#RGB'`（自动补全）、`{ r, g, b }`
- `tolerance`：0~255（默认 10），RGB 三通道各自容差。画面有色差/渐变就调大
- `region`：视频坐标的矩形 `{x,y,w,h}`，省略 = 全屏。找色比找图快得多，区域越限定越快
- `findColor` 未命中返回 `{ found:false, x:-1, y:-1 }`，和 waitImage 一样**不报错**

### `ocrText(region?)` — 识别屏幕文字（OCR）

找图 / 找色都不灵时（文字会变、颜色会变、内容会变），用 OCR 直接读屏幕上的字：

```js
// 全屏识别
const r = await ocrText()
log(r.text)                        // 所有文字，按行用 \n 拼起来
if (r.text.includes('开始游戏')) log('找到了')

// 只识别顶部一块（更快）
const r2 = await ocrText({ x: 0, y: 0, w: 540, h: 300 })

// 找到某一行文字后点它（lines 的坐标是视频坐标，可直接 tap）
const hit = r.lines.find((l) => l.text.includes('领取'))
if (hit) await tap(hit.x, hit.y)
```

- 返回 `{ text, lines }`：`text` 是全部文字（按阅读顺序用 `\n` 连接）；`lines` 是每行 `{ text, score, x, y, w, h }`，坐标是**视频坐标**，可直接 `tap(hit.x, hit.y)`
- `region`：视频坐标矩形 `{x,y,w,h}`，省略 = 全屏。**框小区域能快很多**（全屏一次约 1 秒）
- ⚠️ 需先在「设置 → OCR 模型」下载模型（约 16MB，一次性）；没下载时调用会报错提示去下载
- 识别的是屏幕上的**可见文字**（按钮、数字、聊天等），不是内存里的数据

> 典型用法：`waitImage` 找「大概位置」，`ocrText` 读「具体内容」（倒计时数字、道具数量、可变的公告文字）。

### `setClipboard(text, paste?)` — 写剪贴板 / 粘贴

`text()` 只能发 300 字节（中文每字 3 字节），长文本（激活码、长 URL、整段话）用剪贴板：

```js
await setClipboard('很长的文本……')        // 只写进设备剪贴板
await setClipboard('很长的文本……', true)  // 写剪贴板并立即在设备上触发「粘贴」
```

> 想先写进去、过会儿在某个输入框手动/脚本再粘，用不带 `paste` 的版本；要一步到位就 `paste: true`。

### `log(...)` / `console.log(...)` — 输出日志

```js
log('签到完成')
log('当前计数:', 3)          // 多参数自动空格拼接，非字符串会 JSON 化
console.log('一样的效果')
```

输出显示在脚本面板下方的日志区。

## 完整案例

### 案例 1：每日签到（打开活动 → 领取 → 返回）

```js
log('=== 每日签到开始 ===')

// 回到主页，从干净状态开始
await key('HOME')
await wait(1500)

// 打开 App（先手动放好图标位置，这里点桌面第 2 行第 3 列的图标）
await tap(620, 1500)
await wait(3000)            // 等 App 启动加载

// 进活动页
await tap(900, 300)
await wait(2000)

// 点签到按钮
await tap(540, 1600)
await wait(1000)

// 弹窗"签到成功"，点确定
await tap(540, 1400)
await wait(500)

// 退出：连续返回 3 次回桌面
for (let i = 0; i < 3; i++) {
  await key('BACK')
  await wait(600)
}

log('=== 签到完成 ===')
```

### 案例 2：自动刷短视频（滑动 + 随机停留 + 点赞）

```js
// 刷 20 条视频，每条停留 4~7 秒随机，第 5 条点一次赞
const COUNT = 20

log(`开始刷 ${COUNT} 条视频`)

for (let i = 1; i <= COUNT; i++) {
  // 上滑切换到下一条（从屏幕下 1/4 滑到上 1/4）
  await swipe(540, 1800, 540, 600, 200)

  // 随机停留 4~7 秒，比固定间隔更像真人
  const stay = 4000 + Math.floor(Math.random() * 3000)
  await wait(stay)

  // 每刷 5 条点一次赞（右侧心形按钮的位置）
  if (i % 5 === 0) {
    await tap(980, 1300)
    await wait(500)
    log(`第 ${i} 条已点赞`)
  }

  log(`进度: ${i}/${COUNT}`)
}

log('刷完了')
```

### 案例 5：带容错和进度的长任务

```js
// 每天循环领奖励：某一步失败不影响整体，最后汇总
let ok = 0
let bad = 0

const claim = async (name, x, y) => {
  try {
    await tap(x, y)
    await wait(1200)
    await key('BACK')     // 关掉可能弹的弹窗
    await wait(500)
    ok++
    log(`✔ ${name} 完成`)
  } catch (e) {
    bad++
    log(`✘ ${name} 失败: ${e.message}`)
  }
}

await claim('任务一', 300, 800)
await claim('任务二', 300, 1000)
await claim('任务三', 300, 1200)

log(`全部结束：成功 ${ok} / 失败 ${bad}`)
```

## 脚本里能用什么？

**能用的**：完整 JavaScript 语法——`for` / `if` / `while`、函数、`async/await`、`try/catch`，以及 `Math`（随机数）、`Date`、`JSON` 这些内置对象。上面案例里的 `Math.random()` 就是这么来的。

**不能用的**：`require` / `import`、`process`、文件读写、网络请求——沙箱里没有这些能力，脚本只能操作设备。

## 运行与停止

- **运行**：点「运行」前如果编辑器有未保存的修改会先自动保存；脚本发给当前投屏的设备。快捷键 `Ctrl+S` 保存、`Ctrl+Enter` 运行。
- **同一脚本不能并发跑两份**：已经在跑再点运行会被拒绝，先「停止」。
- **停止**：随时点「停止」，脚本在下一个 API 调用点停下；**按着的触摸/按键会先正确抬起**，不会在手机上留下"手指卡住"。
- **投屏断开**：会话断了脚本会自动中止（报"会话已断开"）。
- 无限循环的脚本（如 `while (true)`）也能被停止——但要记得循环里放 `await wait(...)`，否则会空转占满 CPU 被强制结束。
- **出错会带行号**：脚本抛异常时日志会显示「第 N 行」，对着编辑器行号改那一行就行；**点错误日志会直接跳到那一行并选中**。
- **面板布局**：抽屉右边缘可以拖拽调宽（双击手柄恢复默认）；日志区顶部边缘可以拖拽调高。名称旁的蓝点 = 有未保存的修改。

## 常见坑

| 现象 | 原因与解法 |
|------|-----------|
| 点到了别的位置 | 分辨率 / 横竖屏变过，坐标失效。重新开调试模式量一次 |
| `text` 没输入进去 | 输入框没有焦点。先 `await tap(输入框坐标)` 再 `text` |
| 中文没反应 | 正常应该没问题；若 App 自定义键盘不收 INJECT_TEXT，改用 `setClipboard` + 粘贴键（面板里发） |
| 滑动太快被识别成点击 | `duration` 太短。快扫至少给 100ms 以上 |
| 脚本跑一半不动了 | 大概率在 `wait` 里，点「停止」即可唤醒 |
| `waitImage` 总是超时 | 阈值太高或模板框太大/含动态内容。试着降 `threshold` 到 0.8，模板重截一块更小的 |
| `waitImage` 报「模板不存在」 | 模板没保存成功或名字打错。去脚本面板「截取模板」里确认 |
| 坐标跟着分辨率漂 | 用 `waitImage` 找图代替写死坐标，天然免疫界面偏移 |
| 想让多台设备一起跑 | 二期功能（群控跑脚本），当前版本一次跑一台 |

## API 速查

```js
tap(x, y)                            // 点击
tap(x, y, ms)                        // 长按 ms 毫秒
swipe(x1, y1, x2, y2)                // 滑动（默认 300ms）
swipe(x1, y1, x2, y2, ms)            // 指定时长
stick(xc, yc, xd, yd, ms)            // 推摇杆：中心→方向点→推住 ms（按住心跳 33ms）
touchDown(x, y)                      // 手指按下不抬（低层，一般用 stick）
touchMove(x, y)                      // 按住移动（方向要这样才算得出来）
touchUp()                            // 抬起（幂等，引擎也会自动兜底抬）
text('内容')                         // 输入文本（≤300 字节，支持中文）
setClipboard('长文本')               // 写设备剪贴板
setClipboard('长文本', true)         // 写剪贴板并立即粘贴
key('BACK')                          // 按键（见上方名称表）
key('POWER', ms)                     // 长按按键 ms 毫秒
key('E', 0, 4096)                    // metastate 组合键（4096=Ctrl）
key(4)                               // 直接用 Android keycode
wait(ms)                             // 等待（≤10 分钟）
const p = await waitImage('图名')     // 截屏找图等到出现（≤120 秒）
                                     // p.found ? tap(p.x, p.y) : 跳过
const c = await getPixelColor(x, y)   // 读像素颜色 → { r,g,b,hex }
const q = await findColor('#ff0000')  // 找色 → { found,x,y }（可选 {tolerance,region}）
const r = await ocrText()             // 全屏识别文字 → { text, lines }
const r2 = await ocrText({x,y,w,h})   // 只识别指定区域（更快）
                                     // r.lines[i] = { text,score,x,y,w,h }（视频坐标）
log('...')                           // 输出日志
```
